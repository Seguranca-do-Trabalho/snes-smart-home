# Test Plan V0.2

## Home Assistant + bridge

1. `docker compose up -d homeassistant`
2. Open `http://127.0.0.1:8123` and complete the onboarding.
3. Create a Long-Lived Access Token in Home Assistant.
4. In the shell: `export HA_TOKEN='...'`
5. `docker compose up -d bridge`
6. `curl http://127.0.0.1:8790/entities`
7. `curl http://127.0.0.1:8790/health`

The result should contain only the entities that Home Assistant knows and that the bridge supports. The official Home Assistant documentation exposes `/api/states` for current states and WebSocket at `/api/websocket` for `get_states`, `get_services`, and `state_changed`.

## Test command

After checking the `entity_id` of the light:

```bash
curl -X POST http://127.0.0.1:8790/command \
  -H 'Content-Type: application/json' \
  -d '{"entity_id":"light.sala_light","action":"off"}'
```

For the door:

```bash
curl -X POST http://127.0.0.1:8790/command \
  -H 'Content-Type: application/json' \
  -d '{"entity_id":"cover.garagem_door","action":"open"}'
```

The exact names may vary depending on the `entity_id` generated by Home Assistant; use `/entities` as the source of truth.
